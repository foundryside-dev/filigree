## Context
Between PDR-0004 (2026-06-16) and this record, Filigree shipped five public
releases — 3.0.0 (2026-06-17), 3.0.1 (2026-06-18), 3.1.0 (2026-06-25), 3.2.0 and
3.3.0 (both 2026-09-02) — and wrote no PDR. Decisions were made in hub cells,
tracker issues, owner chat and commit messages. The 2026-10-07 refresh review
(P-1, P-14) found that the workspace still named agent DX as the Now bet while
most work went to federation seams, that one ADR was reversed silently, and that
closes had been recorded against commits that never reached `main` (P-4). This
PDR records those decisions after the fact. Where an outcome can be judged, it
gives a verdict; where it cannot, it says UNKNOWN and why. It decides nothing
new. Forward rulings (D-A…D-K) belong in PDR-0006.

## Verdict on PDR-0002 (Toolkit-DX Now bet) — UNKNOWN (Q4)

PDR-0002 made agent-systems DX the Now bet, led by the Toolkit DX epic
`filigree-18bd3b8c98`, and measured it against the north-star "agent work-loop
completion (claim → close, no dead-end)". The verdict is **UNKNOWN**, not ACCEPT
and not REJECT:

- **Shipped output, unread outcome.** All 16 of the epic's children were
  closed by 2026-06-08, 12 of them on 2026-05-29. All of that happened before
  PDR-0002 was written (2026-06-16), so the bet named work that was already
  done. The epic itself was closed on 2026-06-20 by a sweep ("all child work is
  already terminal"), not by an acceptance verdict.
- **The metric was never measured.** `metrics.md` still shows `BASELINE unset`
  for the north-star, and its 2026-09-30 target has expired. Until Task 0.1
  (2026-10-09), the call log recorded error envelopes as successes and never
  logged schema rejections, so a dead-end rate could not be computed from it.
  Reversal trigger (b), "baseline ≥ 95%", could never fire. Trigger (a), "the
  F1–F7 defects are cosmetic", was never evaluated because no PRD was written.
- **Weak evidence against "dead-ends removed".** The 2026-10-07 review still
  found agent-loop dead-ends: claim-verb bypasses (MCP F1/F3/F4) and orientation
  gaps (LX-01..03). Phase 0 Tasks 0.3 and 0.4 fix them. So the epic did not
  remove every dead-end. Without a rate, though, that does not show whether
  completion moved.
- **The bet was displaced, not superseded.** Roughly 36 of 63 non-merge commits
  since v3.0.0 went to federation, registry and governance work (P-1). The
  "bounded" federation tail (X-4/X-5/X-6) stayed open for 16 weeks.

PDR-0002 stays on record as the last explicit Now bet. In practice it was
superseded by the 4.0 remediation plan (the current Now bet). PDR-0006 records
that formally (plan §1.1). The reading that would turn this UNKNOWN into
ACCEPT or REJECT is the Phase 1.6 baseline taken from the Task 0.1 call logs.

## Rationale
A decision with no record cannot be reversed on purpose. It can only drift.
Writing down what 3.0–3.3 actually decided, with UNKNOWN where nothing was
measured, gives PDR-0006 a true baseline to rule from. It also stops another
session from re-deriving the bet from the stale workspace (P-1). The verdicts are
deliberately conservative: an UNKNOWN that names the missing reading is more
useful than an ACCEPT based on merged children.

## Reversal trigger
Revisit the PDR-0002 verdict when the Phase 1.6 baseline exists. ACCEPT if the
dead-end rate in the Task 0.1 call logs shows the claim → close loop at or above
the owner-set target. REJECT if it shows the Toolkit DX fixes left the loop's
main dead-ends in place. Revisit the C-16 recommendation if WP-2.7's spec keeps
a lead-summary block. In that case, rebase `ecad149` onto the WP-2.7 shape and
do not land it as-is.
